When Outlook goes dark, the mail still lands.

Lifeboat is open-source email continuity for Microsoft 365. During an outage it receives your domain's mail on Cloudflare, gives everyone a web inbox they can reply from, and copies it all back into Outlook when Microsoft returns.

Deploy it yourself See how it works

Runs on your own Cloudflare account. MIT licensed. Early prototype: read the project status before you rely on it.

Cloudflare will not share a domain's MX. So failover is a switch you throw, and Lifeboat is what is waiting on the other side.

How it works

Three states. A person decides when to change them.

  1. 1

    Standby

    MX → example-com.mail.protection.outlook.com

    Microsoft 365 handles mail as usual. Lifeboat sits idle with your directory loaded and every user already enrolled. A health probe checks Microsoft every five minutes and tells admins when it stops answering.

  2. 2

    Outage mode

    MX → route1.mx.cloudflare.net

    An admin declares the outage and switches MX. Every message is written to storage before it is accepted. Users sign in with a password that does not depend on Microsoft, read their mail, and reply from their real address.

  3. 3

    Recovering

    MX → example-com.mail.protection.outlook.com

    Microsoft is back and MX returns to it. Lifeboat writes what it received into each user's Inbox and what they sent into Sent Items, then goes back to standby.

For the people who need their email

  • A sign-in that works when Entra does not

    Each person sets a Lifeboat password in advance, or signs in through Cloudflare Access with an identity provider that is not Microsoft.

  • Replies from their own address

    Outbound mail goes through Cloudflare Email Sending with DKIM aligned to your domain, and threads correctly.

  • An inbox that feels familiar

    Conversations, search, attachments, and a layout that works on a phone.

  • Nothing to tidy up afterwards

    Mail from the outage appears in Outlook as if it had arrived there.

For the admin on call

  • One console for the whole incident

    Declare and end the outage, watch sync progress, and read an audit log of every action. It can sit behind Cloudflare Access.

  • Held mail instead of bounces

    Messages to addresses Lifeboat does not recognise wait for you to assign them.

  • Your account, your data

    One Worker, one D1 database, one R2 bucket. No third party holds your mail.

With thanks to MessageOne

Someone solved this once already.

In the 2000s, company email lived on an Exchange server in a room down the hall, and when that server failed, work stopped. MessageOne, of Austin, Texas, built Email Management Services for exactly that day. An administrator activated it, people carried on from a web inbox, and the mail found its way home once Exchange was running again.

It worked well enough that Dell bought the company in 2008 for about $155 million.

The server down the hall is now someone else's cloud, and the cloud has bad days too. Lifeboat is that same idea rebuilt for Microsoft 365, as software you can read, run on your own account, and change.

Lifeboat is an independent open-source project. It is not affiliated with or endorsed by MessageOne, Dell, Microsoft, or Cloudflare, and it shares no code with Email Management Services.

Project status

A working prototype, and an honest list.

Lifeboat runs end to end on a laptop and passes its test suite. It has not yet been through a live drill against a real Cloudflare zone and a real Microsoft 365 tenant. Treat it as something to evaluate, and run your own drill before an outage does it for you.

  • WorksReceiving, storing, and reading mail, including attachments and aliases.
  • UnprovenSync-back into a real tenant. It uses a Graph technique Microsoft does not document.
  • WorksEnrolment, sign-in, lockout, conversations, search, and the admin console.
  • UnprovenSwitching MX through the Cloudflare API, and sign-in through a real Access application.
  • WorksSending and replying with correct threading, in local development.
  • By designUsers see only mail that arrives after the switch. Earlier mail stays with Microsoft.
Deploy

Set it up on a quiet day.

Everything Lifeboat needs during an outage has to exist before one: the users, their passwords, the sending domain, and a low TTL on your MX record.

  • Your mail domain's DNS on Cloudflare
  • A Workers Paid plan, for sending to any recipient
  • A Microsoft Entra app registration, for sync-back
  • Node.js 22 or later
# try it locally, no Cloudflare account needed
npm install
cp .env.example .env
npm run dev

# then deploy the database, bucket, and Worker
npm run plan
npm run deploy
